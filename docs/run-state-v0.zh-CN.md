# 局内状态与效果合并 v0

路线规划不再只消费地图图结构。规划输入拆为地图、当前资源、阵容、库存与环境五部分，统一通过 `run-state.v0.1` 交换。

## 当前可用

- 资源：生命与上限、护盾、希望与上限、源石锭、指挥等级与经验、行动力、干员上限、零件箱上限。
- 阵容：干员名、职业、是否进阶、是否临时招募。
- 留券：按职业保存券种与数量。路线到达险路尽头时计入取券价值，到达险路小径时计入无法取券的机会成本。
- 收藏品：本地目录记录名称、原文效果和路线相关结构化效果。
- 状态：理想域理念、实托邦方针和追猎后遗物。按当前层数选用早期、中期或晚期效果。
- 每层校准：页面会把人工修正保存到浏览器本地，也可以导出 JSON，并在下一次构建页面时通过 `--run-state` 载入。
- 阶段差量：从第二个检查点开始，导出文件会自动记录资源变化、新招募干员、留券变化、新增收藏品和状态增减，便于后续统计每层成长。

```powershell
python tools/build_route_planner.py --run-state data/my-run-state.json
```

## 自动识别与人工微调的边界

UI 识别应优先读取游戏当前显示的总量，而不是把所有奖励反复累加：

1. 地图页读取行动力、生命、护盾、希望、源石锭、指挥等级与经验、零件箱占用。
2. 战斗奖励页只记录本场增量和券种，不直接改写无法确认的整局总量。
3. 招募完成页记录新干员、职业、临时招募与进阶状态。
4. 收藏品总览页按图标候选加文字 OCR 交叉确认名称。仅识别到数量时保留总数与“待补”数量，不虚构效果。
5. 理想域从地图视觉标记和文字详情确认。暂未标注受影响节点范围时，规划器按全图保守估计，并明确显示提示。
6. 每层结束或进入新层后弹出一次紧凑校准面板。用户只修正差异，然后保存本层快照。

字段使用来源优先级：本层人工修正 > 同帧文字与图标交叉确认 > 单一 OCR > 上一层快照。保存本层快照后，人工锁定解除，下一层 UI 可以再次自动更新。

## 效果合并规则

一次性获得的希望、源石锭、生命上限或干员已经体现在当前 UI 总量中，不从收藏品效果再加一次。持续效果按以下维度合并：

- `node_score` 相加，用于收藏品对特定节点的联动偏好。
- `combat_risk` 相加，与生命比例、阵容填充率和进阶干员数一起修正战斗路线风险。
- `merchant_value_multiplier` 相乘，用于零件售出价值和行商价值修正。
- `bonus_parts_per_combat` 相加，作为每场战斗的额外零件期望。
- `resource_multiplier` 相乘，用于能够证明会改变节点资源产出的效果。
- `information_risk` 相加，用于未揭示路线和未标注理想域作用范围的保守折价。

收藏品原文目录来自 BWIKI。`tools/update_run_state_catalog.py` 可重新抓取完整目录并生成结构化文件。WIKI 防护可能临时拦截 API，此时仓库内置的路线相关种子目录仍可离线使用。

## 尚未自动化

- 干员总览的稳定截图入口和头像模板库。
- 239 件收藏品的完整图标模板，当前更新脚本可获取文字目录，界面内置的是路线相关种子。
- 理想域影响节点的逐节点视觉标注。
- 未知收藏品效果对路线价值的概率模型。

这些缺口不会被当作零影响。界面会保留数量和未知状态，并允许用户在每层校准。
